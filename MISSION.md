# Mission: System Design

## Why
ML Engineer (~14 months in production) planning a job switch. Wants to pass system-design interviews (general and ML-specific), and, since most code now gets written with coding agents (Claude Code, Codex), become the engineer who can judge whether a generated architecture is correct, scalable, reliable, secure and sensible on cost.

## Success looks like
- Can design the classic interview systems (URL shortener → feed → chat → YouTube → payments) from scratch, out loud, explaining the trade-offs.
- Can design ML-specific systems (inference platform, feature store, RAG, LLM serving, fraud detection) with real depth.
- Can explain the mechanism behind "cool" answers (consistent hashing, Kafka, Raft, outbox, etc.): what problem each solves and how it fails.
- Can do back-of-the-envelope capacity estimates on paper in a few minutes.
- Can review an agent-generated architecture and point out bottlenecks, SPOFs and consistency risks.

## Constraints
- Self-learner. Wants lectures only: no exercises or homework (does practice on their own).
- Prefers the books in `resources/` as primary sources. Web only when the books don't cover a topic well.
- Low tolerance for unexplained jargon. Every term gets a hover explanation or a "covered later" note.

## Out of scope
- Phase 0 (networking / OS / DB basics): already known at a basic-to-medium level. Only revisit if the user asks.
