Clocks, pauses & quorums

The short version of Lesson 0006.

Failure detection

Heartbeats + timeout. Too short: slow nodes declared dead → duplicate work, load shifts, cascades. Too long: slow recovery. Gossip spreads heartbeat counters via random peers.

DDIA pp. 280–281 · Xu Ch. 6

Two clocks

Wall clock: date/time, can jump back, roughly comparable across machines. Monotonic: durations only, never goes back, not comparable across machines. Python: time.time() vs time.monotonic().

Clock errors

Drift (200 ppm ≈ 17 s/day unsynced), forced resets, NTP over the internet ≥ ~35 ms, leap seconds, VM pauses, untrusted user devices. Usually silent.

Last write wins

Keeps the highest timestamp. Silently drops a later write whenever clock skew > the gap between writes. Safer: single leader ordering, version numbers, logical clocks.

DDIA Fig. 8-3

Clock = confidence interval

A reading is really [earliest, latest]. Spanner's TrueTime exposes it and waits out ~7 ms of uncertainty before committing.

Process pauses

GC (up to minutes), VM suspend/migration, CPU steal, slow/network disks, swapping, SIGSTOP. A node can freeze anywhere and wake with stale beliefs.

Majority quorum

Decisions need > half the nodes. Only one majority can exist, so no split brain. n nodes survive ⌊(n−1)/2⌋ failures: 3→1, 5→2. Use odd sizes.

Fencing token

Lock service hands out an increasing number with each lease. The resource rejects writes with a token lower than one it has seen. Stops zombie leaders.

DDIA Fig. 8-5

Byzantine fault

A node that lies, not just one that's slow or stale. Normal systems assume nodes are honest; tolerating liars needs much heavier protocols.
