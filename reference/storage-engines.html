Storage engines: LSM-trees & B-trees

The short version of Lesson 0007. Source: DDIA Ch. 3, pp. 70–85.

Index trade-off

Extra structure kept on the side so reads don't scan. Speeds reads, slows every write. Choose indexes from real query patterns.

DDIA p. 71

Hash index (Bitcask)

In-memory map key → byte offset in an append-only log. Fast, but all keys must fit in RAM and range queries are slow.

DDIA pp. 72–75

Segments, compaction, tombstones

Log split into closed segment files. Background compaction keeps only the newest value per key into a new file. Deletes append a tombstone.

DDIA Figs. 3-2, 3-3

SSTable

Segment file sorted by key, each key once. Merge like merge sort; sparse in-memory index (one key per few KB); compressible blocks.

DDIA pp. 76–77

LSM write path

1. append to log (commit log) → 2. insert into sorted memtable → 3. flush full memtable as new SSTable, drop the log → 4. compact in background.

DDIA p. 78 · Xu p. 105

LSM read path

Memtable → newest SSTable → … → oldest. Bloom filter per SSTable says “definitely not here” and skips the disk read. Missing keys are the worst case.

DDIA p. 79 · Xu p. 106

Compaction strategies

Size-tiered: small/new files merged into big/old ones (HBase). Leveled: key range split into small files in levels, more incremental, less space (LevelDB, RocksDB). Cassandra: both.

DDIA p. 79

B-tree

Tree of fixed-size pages (4 KB+), updated in place. Branching factor in the hundreds → 3–4 levels. 500⁴ × 4 KB ≈ 256 TB. Inserts split full pages.

DDIA pp. 79–81

Write-ahead log (redo log)

Every B-tree change is appended to the WAL before touching pages, so a crash mid-split can be repaired. Concurrency via latches.

DDIA p. 82

Write amplification

One logical write → many physical disk writes over time (WAL + page, or repeated compaction). Limits write throughput; wears SSDs.

DDIA p. 84

LSM vs B-tree

LSM: higher write throughput, smaller files; compaction can spike p99 and fall behind (monitor it!). B-tree: faster, predictable reads; one place per key suits transactions.

DDIA pp. 83–85

Who uses what

LSM: RocksDB, LevelDB, Cassandra, HBase, Lucene (similar). B-tree: PostgreSQL, MySQL InnoDB, most relational DBs. Flink and Kafka Streams keep state in RocksDB.
