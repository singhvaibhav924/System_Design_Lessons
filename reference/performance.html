Performance cheat sheet

The short version of Lesson 0002.

Throughput

Work done per second (QPS/RPS, records/s). The key number for batch systems.

Response time

Client-observed time for one request = service time + queueing + network. The key number for online systems. Everyday "latency" usually means this.

DDIA p. 14

Bandwidth

The maximum a link can carry per second. Throughput is what actually gets through.

Percentiles

p50 = median, the typical request. p95/p99/p999 = the tail. "p99 = X" means 1% of requests take X or longer. The mean describes nobody.

Why the tail matters

Users send many requests; slow requests often come from the heaviest users (Amazon targets p99.9); SLOs are written in percentiles. But p99.99 is usually too costly to chase.

Fan-out amplification

P(user request slow) = 1 − (1 − p)N. 100 backends × 1% slow → 63% slow. Each backend's p99 becomes the user's p50.

Dean & Barroso, "The Tail at Scale"

Little's Law

In-flight requests = throughput × response time. 2,000 req/s × 50 ms = 100 concurrent. If response time doubles, so does the concurrency you need.

Utilization vs waiting

Simple queue: response = work ÷ (1 − utilization). 50% busy → 2×, 80% → 5×, 95% → 20× the work time. Keep headroom.

Measuring

Measure on the client side. Never average percentiles; merge histograms. Load-test with traffic that keeps arriving whether or not the system is slow.
